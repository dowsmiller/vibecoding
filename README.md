# Vibe-Coding for Medievalists: How to Use LLMs to Safely and Reliably Accelerate Your Research Workflows
“Vibe-coding”, the practice of directing large language models to write, run, and improve code through natural-language instruction rather than active human programming, has moved quickly from a curiosity to a genuinely viable research method. For medievalists without formal training in coding and software development, it offers a tempting route to bespoke digital tools that have hitherto been out of reach for single-scholar, short-term, or underfunded projects. However, the speed and confidence with which scholars can produce tools using LLMs also mean that vibe-coding can result in fragile, silently broken, or downright misleading tools if it is used without discipline and careful, algorithmic thinking.

This workshop teaches medievalists, whatever their coding background, how to vibe-code effectively and safely, and to recognise when the technique may give trustworthy results and when it will not. We begin by situating vibe-coding within the broader LLM-assisted research landscape, distinguishing it from adjacent practices such as AI-based transcription tools and direct AI-led data analysis. We then address a question central to responsible use: when can we trust the outputs of vibe-coded tools? The answer to this question is predominantly one of verifiability – tasks with an easily checkable output, such as valid TEI-XML encodings automatically produced from a manual transcription, are far safer territory for vibe-coding than tasks for which the correctness cannot easily be confirmed, as in cases of quantitative data analysis. Participants will discuss a framework of criteria that they can apply to their own projects.

The practical core of the session is then concerned with questions of technique, covering the following areas:
- How to select the right tools and environments for a vibe-coded project.
- How to write prompts that precisely specify tool features and performance.
- How to work through planning phases rather than requesting finished code outright.
- How to decide on preferred packages, libraries, and architecture in advance so as to minimise the arbitrary choices made by the LLM.
- How to test initial outputs, conduct midway code reviews, and iterate improvements incrementally.
- How to safely use version control with systems and platforms like Git and GitHub, and to maintain awareness of changes made by a model.

These principles are consolidated through a guided project, in which participants will vibe-code a simple Python/Flask web application for basic TEI encoding. This project is intended to give participants experience of the full vibe-coding pipeline, from planning, through to incremental building, iterative checking and improvement, and output verification.
